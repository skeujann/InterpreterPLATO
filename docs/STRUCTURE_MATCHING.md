# 结构匹配（5.5.2）

按用户要求，解释器默认忽略立体信息。配置为 `plato.ignore_stereochemistry=true`。
使用 RDKit 移除原子及双键的立体标记后生成规范结构键，保留同位素、电荷、键级、组分。
因此 R/S、E/Z 和未指定构型可匹配同一连接结构；结构异构体、同位素替换、盐型不会因此混合。

## 缓存与来源

原缓存键、SMILES、InChIKey、提交记录和原始响应不修改。
匹配时检查同组已归档条目，以解析后的完整靶点记录（忽略记录顺序）比较一致性。
同组输出一致时，优先选择未指定构型的既有缓存，否则按规范 SMILES 排序选择固定代表。
结果审计的 `plato_inputs.<side>.structure_matching` 同时保留请求结构、代表查询结构、
组内成员及是否跨构型复用。组内数据损坏或靶点预测冲突均明确报错，不任意选一份或取并集。
忽略构型是一项解释器匹配策略，不把未查询构型标成已经查询，也不证明不同构型药效相同。

具体药理作用的文献条目继续绑定原文对应的完整结构，不自动外推为所有构型的药效证据。
PLATO 采集工具仍发送调用者提供的准确 SMILES，并保留提交记录。

## 恢复精确匹配

工程入口加 `--respect-stereochemistry`；API 或配置文件设置
`{"plato": {"ignore_stereochemistry": false}}`。来源审批方式与结构匹配开关互相独立。

第五例已有独立补充实验：16 种理论构型分别查询 PLATO，响应和靶点解析结果均一致。
该观察只适用于这次阿扎胞苷结构及已保存的响应；默认策略不会把它当成所有药物的实验结论。
